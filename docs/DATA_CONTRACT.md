# 데이터 명세

## 저장 단위

- 가격: 정수 **만원**, 화면은 ÷10,000 하여 억원으로 표시
- 전용면적: 양의 실수 ㎡; 평당 금액은 1평=3.305785㎡ 적용
- 좌표: latitude=위도, longitude=경도 (WGS84). 대한민국 범위 검증
- 계약일: 날짜 YYYY-MM-DD; 계약월: YYYYMM
- 수집/확인시각: 시간대 있는 ISO 8601 입력 → UTC 초 단위 정규화
- 법정동 지역코드: 5자리 문자열. 실제 명칭과의 일치 여부는 수집자가 확인

## 매물 CSV / JSON

아파트 매매 자료만 넣는다. 임대보증금이나 월세를 price_man에 넣지 않는다.
CSV는 UTF-8(BOM 허용), 첫 행은 아래 영문 열 이름. JSON은 같은 객체를 담은 최상위 배열이다.
파일 제한 10MB / 50,000행. 필수 열이 잘못되면 전체 파일을 거절한다. 추가 필드는 저장하지 않는다.

| 열 | 필수 | 예 / 규칙 |
|---|---|---|
| source | O | 공급자 식별자, 파일명보다 고정된 공급자명 사용 |
| listing_id | O | 공급자 안에서 안정적이고 재사용하지 않는 광고 ID |
| observed_at | O | 2026-09-19T15:00:00+09:00, 공급자가 마지막으로 실제 확인한 시각 |
| region_code | O | 11680 |
| apartment | O | 단지명, 실거래 단지명과 정확히 같아야 비교 가능 |
| address | O | 서울특별시 강남구 역삼동 123-4, 전체 주소 |
| dong | O | 역삼동 |
| area_m2 | O | 84.9 |
| price_man | O | 150000 = 15억원; 소수 만원 미허용 |
| floor | X | 12, 없으면 빈 값 |
| status | O | active / withdrawn / sold |
| latitude | X | 37.5008, 경도와 함께 제공하거나 둘 다 비움 |
| longitude | X | 127.0365 |
| source_url | X | http/https 원본 링크, 없으면 빈 값 |

`observed_at`을 가져오기 시각으로 임의 덮어쓰면 안 된다. 오래된 광고를 현재 매물로 바꾸지 않기 위한 조건이다.
시간대 없는 날짜, 현재보다 5분을 초과하는 미래 날짜를 거절한다. 허용된 오차 범위의 미래 행도 현재 시점이 도달하기 전까지는 집계하지 않는다.
같은 출처+ID+시각+내용의 재가져오기는 0건 추가한다. 동일 키에 다른 내용이면 거절하고 롤백한다.
확인시각은 초 단위이므로 한 ID의 같은 초에 여러 상태를 보내지 않는다.

```json
[
  {
    "source": "licensed-partner",
    "listing_id": "APT-0001",
    "observed_at": "2026-09-19T15:00:00+09:00",
    "region_code": "11680",
    "apartment": "예시 단지",
    "address": "서울특별시 강남구 역삼동 123-4",
    "dong": "역삼동",
    "area_m2": 84.9,
    "price_man": 150000,
    "floor": 12,
    "status": "active",
    "latitude": null,
    "longitude": null,
    "source_url": ""
  }
]
```

이 예시는 입력 형식 설명용이며 실제 매물이 아니다. 정적 예시 날짜를 최신 시각으로 자동 치환하지 않는다.
피드는 같은 배열을 HTTP 200 응답 본문으로 제공해야 하며 리디렉션은 허용하지 않는다. Bearer 토큰은 환경변수로만 전달한다.
이 MVP 피드는 한 응답 스냅샷/증분 배열을 처리하며 공급자 고유 구조·페이지네이션은 변환 어댑터가 필요하다.

## 테이블

| 테이블 | 역할 / 키 |
|---|---|
| trades | 실거래 현재 수집본. 정수 id, 지역·월·출처 범위로 교체, raw_json 보존 |
| listing_snapshots | 관측시각별 가격·상태. UNIQUE(source, listing_id, observed_at) |
| geocodes | address 기본키, 좌표·provider·updated_at |
| collection_runs | 시작/종료 시각, 범위, 성공/실패/진행, 반영 건수 |
| metadata | key/value; demo_seeded 기준일 |

SQLite `user_version=1`. 스키마 변경 시 다음 버전의 명시적 마이그레이션을 추가한다.
`trades.raw_json`은 받은 item 필드 전체이며 XML 원문 자체나 과거 수집 회차 전체를 보존하는 저장소는 아니다.
거래 속성이 같아도 서로 다른 거래일 수 있으므로 행을 해시로 강제 중복 제거하지 않는다. 대신 지역·월 전체 교체로 재수집 중복을 막는다.
실거래 페이지 수집 중 totalCount 변경/누락을 감지하지만 총수는 같은 상태로 원천이 바뀌는 상황까지 완전히 검출할 수는 없다. 재조회로 조정한다.

## 데이터 품질과 비교 기준

`cdealType` O/Y/1 또는 해제일 존재 시 해제로 판정하고 기본 조회에서 제외한다.
지번이 없으면 주소를 비워 좌표가 있는 것처럼 처리하지 않는다. 조회는 저장 좌표 우선, 다음으로 주소 캐시를 사용한다.
매물 최신 스냅샷을 먼저 결정한 후 active/유효기간/필터를 적용한다. 반대로 적용하면 종료 매물의 옛 active가 되살아나므로 금지한다.
호가 비교는 정확한 전체 주소+단지명과 매물 면적 ±5%로 제한한다. 명칭 표준화가 안 되면 비교 표본에서 빠지며 임의 유사 매칭을 하지 않는다.
동일 공급자 ID 이력은 관리하지만 공급자 간 동일 주택 중복 제거는 구현하지 않는다.

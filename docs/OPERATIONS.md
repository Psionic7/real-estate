# Windows 운영 가이드

## 첫 실행과 실제 운영 전환

1. `scripts/setup.ps1`로 설치하거나 준비된 `.venv`를 사용한다.
2. `run.bat` 실행 후 기본 지역인 용인시 수지구의 지도와 실거래 필터를 확인한다.
3. `.env`에 발급 키를 넣고 앱을 다시 시작한다.
4. 데이터 관리에서 지역코드/이름이 일치하는 한 달을 수집한다.
5. 수집 범위·건수·금액·해제를 공식 자료와 대조한 뒤 주소 좌표를 수집한다.
6. 제공처의 허용된 매물을 표준 CSV/JSON으로 변환한다. 가격 단위와 observed_at을 검수한다.

새로고침은 SQLite를 다시 읽는다. .env 변경은 앱 재시작이 필요하다.
앱은 실제 데이터 DB만 사용한다. 좌표가 없어도 배경지도가 표시되며, 단지 위치는 카카오 좌표 수집 후 표시된다.

## 권장 수집 주기

| 대상 | 운영안 |
|---|---|
| 실거래 | 일 1회 최근 3개월, 주 1회 최근 12개월, 분기마다 전체 보유기간 재수집 |
| 매물 | 제공처 업데이트 주기에 맞춰 일 1~4회 (계약·한도에 맞춰 조정) |
| 주소 좌표 | 신규 주소 수집 후 제한된 묶음으로 처리 |
| 백업 | 일 1회, DB 변경 전 추가 백업 |

위 일정은 아직 자동 등록되지 않았다. 아래 절차로 사용자가 운영 주기를 정해 등록할 수 있다.
현재 수집 스크립트는 실거래와 좌표만 갱신하며 매물 피드는 별도 `fetch-listings` 명령을 작업으로 등록한다.

## 작업 스케줄러 설정 예

Windows 작업 스케줄러에서 ‘작업 만들기’를 선택한다.

- 프로그램: `powershell.exe`
- 인수: `-NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File "C:\Users\Psionic\Documents\ChatGPT\kh_project\scripts\collect_daily.ps1" -Region 11680 -RegionName "서울특별시 강남구" -Months 3`
- 시작 위치: `C:\Users\Psionic\Documents\ChatGPT\kh_project`
- 트리거 예: 매일 06:00 (운영자가 선택)
- 중복 실행: 새 인스턴스를 시작하지 않음
- 실행 계정: 해당 프로젝트와 .env를 읽고 DB 폴더에 쓸 수 있는 사용자

여러 지역은 작업이 겹치지 않도록 순차 실행한다. 수집 화면과 CLI에서 같은 지역·월을 동시에 갱신하지 않는다.
스케줄러 마지막 실행 결과와 앱의 collection_runs를 확인한다. 현재 앱 자체의 이메일·메신저 알림은 없다.
좌표 키가 없으면 collect_daily의 좌표 단계는 실패하므로 키를 설정하거나 실거래 CLI만 작업으로 등록한다.

## 백업 및 복구

운영 중 WAL 파일을 제외하고 .sqlite3 파일만 복사하면 최근 변경이 누락될 수 있다. SQLite backup API를 쓰는 명령을 사용한다.

```powershell
.\.venv\Scripts\python.exe -m estate.cli backup .\backups\estate-20260919.sqlite3
```

대상 파일이 있으면 덮어쓰지 않는다. 새 날짜/시간 이름을 지정한다. 백업 폴더도 별도 디스크로 추가 복제한다.
권장 보존안은 일별 7개·주별 4개·월별 12개이며 자동 삭제 로직은 포함하지 않았다.

복구 시 앱과 모든 수집 작업을 종료하고 기존 data 폴더 전체를 다른 위치에 보관한다.
백업을 새 빈 data 폴더의 estate.sqlite3로 복사한 후 재시작한다. 기존 WAL/SHM이 새 DB와 섞이지 않도록 새 폴더를 쓴다.
경로는 `.env`의 REAL_ESTATE_DATA_DIR로 변경할 수 있다. 재시작 후 수집 범위와 건수를 확인한다.

## 장애 대응

| 증상 | 확인/조치 |
|---|---|
| API 키 오류 | 상세 자료 API의 활용신청 승인, 키 종류, 호출량, 유효기간 확인 |
| 수집 중 네트워크 실패 | HTTP 429/5xx 자동 재시도 후 실패 기록; 해당 월 재수집 |
| 날짜/총건수 검증 실패 | 기존 DB 유지, 응답 명세 및 원천 변경 확인 |
| 매물 0건 | 최신 상태, 실제 확인 날짜와 유효기간, 가격/지역 필터 확인 |
| 지도에 표시 없음 | 좌표 미확정 건수, 카카오 키, 지번 주소, 인터넷 타일 접근 확인 |
| SQLite locked | 동시 수집 중지, 로컬 디스크 확인, 30초 대기 후 작업 재시도 |
| running 기록이 남음 | 프로세스 종료 여부 확인, 동일 범위 재수집. 무조건 성공으로 변경하지 않음 |
| 앱이 느림 | 필터 범위와 DB 크기 점검. 대량 데이터는 SQL 필터/집계 최적화 후 확대 |

## 접근과 성능

기본 바인딩은 127.0.0.1이므로 같은 PC에서 사용한다. 외부 제공 전 인증, 수집 관리자 권한, HTTPS, 업로드 제한을 운영 환경에 맞게 구성해야 한다.
API 키는 .env에 두고 로그/화면 오류에 URL이나 인증 헤더를 출력하지 않는다. DB와 백업에는 수집된 데이터가 포함되므로 계정 접근을 제한한다.
실제 운영 승인 기준은 화면 응답시간·행수·주소 매칭률·오류 비율을 측정한 후 정한다. MVP에는 전국 규모 성능 벤치마크가 없다.
